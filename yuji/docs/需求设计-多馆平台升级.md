# 悦己瑜伽 · 多馆平台升级需求设计

> 版本：v1.1（需求已确认，开发中）
> 日期：2026-10-02
> 升级方向：单馆工具 → 城市多馆平台（超级管理员 / 馆主 / 学员 三级角色）

---

## 1. 背景与目标

当前小程序是「单馆模式」：全局唯一管理员（口令 `yoga2026` 自助升级），课程/套餐/会员不区分场馆，无城市概念。

本次升级目标：

1. 引入**超级管理员**角色，负责创建场馆、任免馆主
2. 引入**多场馆**体系：普通用户按城市浏览瑜伽馆及其课程
3. 馆主只管理**自己名下的场馆**，可查看「今天各时间点课程的预约会员」
4. 课时/套餐**按馆隔离**，账目清晰，无跨馆结算

## 2. 角色与权限体系

### 2.1 角色定义

| 角色 | 英文标识 | 如何产生 | 能做什么 |
|------|---------|---------|---------|
| 超级管理员 | `superadmin` | 手机号写死于云函数配置：`17611028882`（绑定该手机号的账号登录后自动升级） | 创建/编辑/关闭场馆；指定、邀请、撤销馆主；查看全平台数据 |
| 馆主 | `owner` | 仅由超级管理员任命（从注册用户中挑选，或微信分享邀请对方接受） | 管理名下场馆的课程、套餐、预约、会员、统计、公告 |
| 学员 | `student` | 微信登录后默认角色 | 选城市 → 浏览瑜伽馆 → 查看课程 → 购课时 → 预约/签到 |

### 2.2 权限矩阵

| 操作 | 学员 | 馆主 | 超级管理员 |
|------|:---:|:---:|:---:|
| 浏览馆列表/课程 | ✅ | ✅ | ✅ |
| 预约/取消/签到 | ✅ | ✅ | ✅ |
| 创建/编辑场馆 | ❌ | ❌ | ✅ |
| 课程增删改 | ❌ | 本馆 ✅ | 全部 ✅ |
| 套餐增删改 | ❌ | 本馆 ✅ | 全部 ✅ |
| 查看预约/会员/统计 | ❌ | 本馆 ✅ | 全部 ✅ |
| 指定/撤销馆主 | ❌ | ❌ | ✅ |
| 生成馆主邀请 | ❌ | ❌ | ✅ |

### 2.3 超级管理员规则（重要）

- 云函数 `login` 中写死：`SUPER_ADMIN_PHONES = ['17611028882']`
- 触发时机：登录时、绑定手机号成功后，若 `user.phone` 命中名单 → `role = 'superadmin'`
- **移除**现有 `bindAdmin` 口令自助升级（删除 `ADMIN_PASSWORD` 逻辑与「馆主入口」口令弹窗），馆主一律由超管产生，杜绝自助提权

> ⚠️ 风险提示（需你知晓）：若小程序为**个人主体**，手机号只能手动输入（无微信官方快速验证），理论上他人可输入 `17611028882` 冒充超管。缓解方案：云函数同时支持 `SUPER_ADMIN_OPENIDS` 名单兜底——你用该手机号登录一次后，从云开发控制台 users 集合复制 openid 填入即可双保险。上线商用前建议升级企业主体并启用微信手机号快速验证。

### 2.4 馆主任免规则

- **指定**：超管在「平台管理 → 馆详情」搜索注册用户（昵称/手机号），选中即设为馆主，**即时生效，无需对方确认**
- **邀请**：超管生成分享卡片（微信好友/群），对方点开落地页 → 展示「邀请你成为『XX瑜伽馆』馆主」→ 确认接受后生效
- **撤销**：超管可将某馆馆主降级为学员；该馆若再无馆主，馆进入「待任命」状态（学员端仍可见可约课，后台功能冻结）
- 一馆一馆主；一个人可同时担任多个馆的馆主
- 邀请链接有效期 7 天，过期自动失效

## 3. 数据模型设计

### 3.1 新增集合

```
gyms（场馆）
{
  _id, name, city, address, phone, images[], desc,
  status: 'active' | 'closed',       // closed 馆不再对学员展示
  ownerOpenid: '',                    // 当前馆主（权威来源，空 = 待任命）
  locateEnabled: false,               // 馆主是否开启了场馆定位（坐标）
  latitude: 0, longitude: 0,          // 场馆坐标（GCJ-02，馆主地图选点录入）
  courseCount, createTime, updateTime
}

invitations（馆主邀请）
{
  _id, gymId, gymName, invitedBy,     // 超管 openid
  status: 'pending' | 'accepted' | 'revoked' | 'expired',
  expireAt, createTime, acceptTime, acceptOpenid
}
```

### 3.2 存量集合改造（全部增加 gymId 维度）

| 集合 | 新增字段 | 说明 |
|------|---------|------|
| `users` | `role` 枚举改为 `student/owner/superadmin` | 冗余标记便于客户端判断；权威判定以 `gyms.ownerOpenid` 为准，任免时同步更新 |
| `course` | `gymId` | 课程归属馆 |
| `order` | `gymId` | 预约归属馆 |
| `package` | `gymId` | 套餐由各馆自行定义 |
| `users.packages[]` | `gymId` | **用户课时按馆隔离**：A 馆课时只能约 A 馆的课 |
| `signin` / `hourslog` | `gymId` | 签到与课时流水按馆记录 |
| `notice` | `gymId` | 馆公告；`gymId = ''` 表示平台公告（超管发布） |

### 3.3 城市数据

- 内置精简版全国地级市数据（约 340 条，~20KB）到 `utils/cities.js`
- 首页顶部城市选择器：当前城市 + 热门城市（北上广深杭蓉等）+ 字母索引搜索
- **定位与距离排序（已确认方案）**：
  - 馆主在场馆设置里可开启「场馆定位」，地图选点录入坐标（GCJ-02）；未开启则无坐标
  - 学员端已授权定位：同城开了定位的馆按距离由近到远排前，无坐标馆靠后（创建时间倒序），跨城馆不展示
  - 学员端未授权定位：按当前城市过滤展示 + 提示「开启定位可查看距离」
  - 距离用 Haversine 公式客户端本地计算（展示「距您 x.x km」），不依赖地图 SDK 付费接口
  - v2 接入 `wx.getFuzzyLocation` + 腾讯位置服务逆地编码自动识别城市（Key 存云函数侧，需先通过小程序后台「位置信息」类目审核）


## 4. 关键流程

### 4.1 登录（微信授权）

1. 进入小程序 → 静默登录（`wx.cloud` openid 注册/识别）→ 默认 `student`
2. 首次使用引导完善头像昵称（微信官方头像昵称填写组件，**不强制、不阻断**，符合平台审核规范）
3. 已绑定超管手机号的账号，登录后自动获得 `superadmin`
4. 登录返回体增加 `myGyms`（名下场馆列表），客户端据此显示「馆主后台」入口

### 4.2 学员浏览与预约

```
首页（城市选择器 + 馆列表卡片）
  └→ 馆详情（馆信息 + 按日期的课程表）
        └→ 课程详情（展示所属馆）→ 预约（校验该馆剩余课时）
              ├─ 有课时 → 扣该馆课时，生成预约
              └─ 无课时 → 引导购买该馆套餐
```

- 「我的课时」页按馆分组展示（每馆一张卡片：馆名 + 剩余课时 + 明细）

### 4.3 馆主查看今日预约（重点需求）

馆主后台 → 预约管理，默认定位**今天**：

- 日期 Tab：**今天 / 明天 / 后天 / 全部**
- 今天视图按课程时间轴分组：

```
09:30  哈他瑜伽（王老师）          已约 3/10
   ├ 李女士  176****8812  已签到
   ├ 张女士  138****2233  待上课
   └ ...
15:00  阴瑜伽（刘老师）            已约 5/12
   └ ...
```

- 每条预约支持：签到 / 取消（退回课时）
- 支持按会员昵称/手机号搜索

### 4.4 超管任免馆主

```
平台管理（超管专属页）
  ├ 馆列表：创建馆 / 编辑 / 关闭
  └ 馆详情
       ├ 方式一：搜索注册用户（昵称/手机号）→ 选中 → 即时设为馆主
       └ 方式二：生成邀请 → 转发微信 → 对方落地页确认 → 成为馆主
```

邀请落地页：`pages/invite/owner?gymId=xxx&inviteId=xxx`，校验邀请状态与有效期，展示馆信息 + 接受/拒绝。

### 4.5 公告与订阅消息推送（已确认方案）

- **发布方**：超级管理员可发平台公告（全员可见）；**馆主可发本馆公告，所有学员可见**（馆详情页公告栏）
- **发布流程**：编辑公告 → 发布 → 选择「是否推送给当前场馆所有学员」：
  - 推送 → 云函数遍历该馆有课时/预约记录的学员，逐条下发**微信订阅消息**（一次性授权，需学员曾点过「订阅通知」；未订阅者静默跳过，不报错）
  - 不推送 → 公告仅展示在馆详情页
- **订阅引导**：馆详情页/预约成功页放「订阅场馆通知」按钮（`wx.requestSubscribeMessage`），点一次收一条
- **模板**：小程序后台「订阅消息」申领公告类模板，模板 ID 填入云函数配置（上线前申领）
- **降级**：模板未申领或学员未订阅时自动跳过推送，公告功能不受影响

## 6. 云函数改造清单

| 云函数 | 改造内容 |
|--------|---------|
| `login` | 移除口令 `bindAdmin`；新增手机号超管判定；登录返回 `myGyms` |
| `gym` | **新增**：`create / update / list(按城市) / detail / close / setOwner(搜索指定) / invite(生成) / acceptInvite(接受) / revokeOwner` |
| `course` | 全部 action 增加 `gymId` 入参；权限 `assertAdmin` → `assertGymOwner(gymId)`（超管放行） |

| `notice` | 馆公告 + 平台公告（`gymId=''`，仅超管） |
| `init` | 创建 `gyms/invitations` 集合；**数据迁移**：建一个「默认场馆」，把现有课程/套餐/预约/会员数据打上其 `gymId`，现有 admin 用户迁移为其馆主 |

## 7. 数据迁移方案（一次性）

1. `init` 云函数新增 `migrate` action（幂等，可重复执行）
2. 创建默认馆「悦己瑜伽（默认馆）」→ 回填所有存量数据的 `gymId`
3. 现有 `role='admin'` 用户 → 改为该馆 `ownerOpenid` + `role='owner'`
4. 迁移完成后在云开发控制台核对：无 `gymId` 的 course/order/package 记录数 = 0

## 8. 安全与合规注意

1. **超管手机号写死于服务端**（云函数），客户端不持有名单
2. 手动输入手机号（个人主体降级方案）存在冒充风险 → 提供 openid 白名单兜底（见 2.3）
3. 所有写操作权限校验统一收敛到云函数侧：`assertSuperAdmin / assertGymOwner`，客户端角色仅做 UI 展示
4. 地图/定位：v1 不引入地图 SDK；v2 若上定位，使用腾讯位置服务（Key 存云函数），并先通过小程序后台「位置信息」类目申请
5. 分享邀请链接带 `inviteId`，服务端校验状态与有效期，防止越权接受
