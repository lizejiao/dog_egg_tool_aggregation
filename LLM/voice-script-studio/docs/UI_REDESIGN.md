# 前端重构技术方案（UI Redesign）

> 状态：**全部阶段已完成（2026-11-15）：P0 设计 → P1 脚手架 → P2-0 后端 → P2a/P2b/P2c 三页迁移 → P3 上线（8410 服务新版，旧版归档）**
> 配套原型：`design/` 三页（Vue 3 + proto.css，交互可体验），本文档为唯一施工依据

## 1. 背景与目标

现有前端为原生 JS 单页（816 行 app.js + 8 个全局变量 + 18 处手动状态同步），
随着功能演进（级联选择、素材库、双引擎、多格式下载）出现三类问题：

1. **状态同步靠自觉**：一处数据变更需手动刷新多处视图，易漏（已实际发生过）
2. **维护成本上升**：单文件持续膨胀，innerHTML 拼接 + 手动转义有 XSS 风险面
3. **信息架构不适配**：页面布局经多轮修补（音色库三次重组），整体动线已偏离初始设计

重构目标：**组件化 + 响应式状态**，后端 API 零改动，功能对等迁移后替换旧版。

## 2. 技术选型（已确认）

| 层 | 选择 | 决策理由 |
|---|---|---|
| 框架 | **Vue 3**（Composition API + `<script setup>`） | 响应式消除手动同步；模板语法对 HTML 背景最友好；中文生态好 |
| 构建 | **Vite 5** | 秒级 HMR，设计调优期核心生产力 |
| UI 库 | **无——proto.css 自定义样式 + 少量自研基础组件** | 2026-11-15 修订：Element Plus 试点后放弃——其默认样式与本设计冲突严重，覆盖层"对抗式"修补不可维护；本项目无复杂控件需求（日期/级联/表格均用不到），自研滑杆/进度条等每个仅数十行，视觉控制权 100% 自持。原版视觉（proto.css，用户已确认）直接沿用 |
| 状态 | **Pinia** | 官方轻量方案；三个 store（音色/引擎/任务） |
| HTTP | 平移现有 `api()` 封装 | 后端 REST API 一行不动 |

**明确不引入**：TypeScript（后续可选）、Tailwind、任何 UI 组件库。
**风格**：proto.css 蓝白专业风（#409eff 主色，紧凑规格：panel 8px 圆角/18px 内边距、
按钮 5px 圆角、徽章 10px 圆角）。

## 3. 页面信息架构

三个一级页面，顶栏导航切换：

```
工作台（主页）＝ 合成全流程 + 任务监控 + 历史
素材库    ＝ 素材流水线（录音/上传/列表）+ 引擎预置音色
设置      ＝ 引擎卡片（apiKey/代理/模型串/连接测试/暖机）
```

关键决策（相对旧版的变更）：

1. **工作台改步骤向导**：①选引擎 → ②选音色（级联）→ ③合成。级联逻辑显性化为步骤进度，
   "选错引擎配音色"在交互上不可能发生
2. **历史页合并进工作台右侧**：下载/重试/断点续跑是合成的自然延伸，不再单独一页
3. **素材库保持既定动线**：录音 → 上传 → 素材列表（左列流水线）；右列引擎预置音色
   （素材=原材料，注册=升级动作，音色=可合成状态——三段式领域模型已定型，不回退）
4. **保留的功能细节**：双按钮（保存素材/注册引擎）、引擎徽章矩阵、30 秒前置校验、
   三格式下载（WAV/M4A/MP3）、试听缓存机制

#### 4.1.1 能力驱动的动态交互（2026-11-15 补充，用户确认）

**空音色守卫**：音色列表按所选引擎动态拉取（=该引擎注册的音色 ∪ 该引擎预置音色）；
该引擎无任何可用音色时：
- 音色下拉显示引导文案「该引擎暂无可用音色」
- **「开始合成」按钮置灰禁用**，按钮旁提示：「请到素材库 → 音色管理，为该引擎注册音色」
- 目的：把"本地引擎无音色"类失败从合成后报错前置为点击前引导

**合成参数动态渲染**：参数面板按引擎能力矩阵渲染，**不支持的参数不显示**（不置灰）。
能力数据维护在**后端 Provider 的 Caps 声明**（`supported_params` 字段，与
`supports_emotion_tags` 同模式），前端订阅渲染，禁止前端硬编码——引擎能力变更只改一处。

当前真实能力矩阵（P2 实现的依据，后端补齐差距）：

| 参数 | Fish 云端 | CosyVoice3 本地 | 能力来源 |
|---|---|---|---|
| 语速 speed | ✓（prosody.speed） | ⚠️ 模型支持、适配器待接（P2 补） | 模型原生 |
| 段间/段落停顿 | ✓ | ✓ | 拼接层（全引擎一致） |
| 音量 volume | ✓（prosody.volume，待接） | ✗ 不显示 | 模型原生 |
| 情绪标签 | ✓（15000+ 标签） | 部分（[laughter] 等，语义不同→统一剥离） | 模型原生 |

### 4.2 素材库（design/library.html）

```
行 1（左右并排等高）：直接录音克隆 ｜ 上传克隆音色 —— **纯素材采集入口**
  仅：录音/上传 + 逐字稿 + 声音素材名称* + [保存素材]（单一按钮，无注册动作）
  保存后进入素材库；注册统一走音色管理的「注册新音色」表单
行 2（左右并排等高）：我的声音素材库 ｜ 音色管理
  素材卡（素材级操作）：试听 / 下载参考音频 / 复制逐字稿 / 删除（删素材提示音色依赖）
  音色管理（唯一注册入口）：顶部「注册新音色」表单（素材→引擎→音色名称*唯一→注册）
           + 引擎页签（CosyVoice3 本地 / Fish 云端），页签内含
             「我的音色」（注册产物，可删）与「预置音色」（云端专属，仅试听）
  Fish 页签专属：页签栏右侧「🔄 同步云端音色」按钮 + 提示条——云端音色在
    fish.audio/zh-CN/app/my-voices/ 管理（免费 API 无创建配额，网页端创建后同步）
```

> 布局修订（2026-11-15 用户确认 ×4）：
> **领域模型升级**——声音素材（原材料）注册引擎后创造"音色"（新实体，自有名称、
> 引擎归属）。注册必填音色名称且**同一引擎内唯一**（跨引擎可重名），名称即
> 使用说明（可命名"我的演讲声-本地版/-云端版"区分同素材多注册）。
> 预置音色并入音色管理对应引擎页签（底部独立区取消）；删音色不影响素材，
> 删素材时提示音色依赖。P2 后端需新增 voice 实体（name/engine/material_id/state）
> 并迁移现有 registrations 数据。

## 8. 风险与对策

| 风险 | 对策 |
