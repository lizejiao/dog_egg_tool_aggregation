ARCHITECTURE BLUEPRINT

企业级支付系统架构 · 智能路由与多通道银行对接

面向持牌消费金融场景的资金执行层设计：承接信贷核心的放款（代付）与还款（代扣 / 批扣）两大资金动作， 维护「收款特约商户账户 + 放款支付账户」双账户体系，通过适配器模式统一封装银联 / 网联 / 银行直连 / 第三方支付通道， 以微服务 + 规则引擎实现智能路由择优，全链路保障资金安全与账务最终一致。

微服务架构 适配器模式 · 配置化接入 规则引擎智能路由 状态机驱动 全链路幂等 最终一致性 差错池 / 挂账 符合《银行卡收单业务管理办法》

业务定位与双账户体系

支付系统是信贷核心的资金执行层，向上承接业务指令，向下屏蔽通道差异，横向保障账实一致。

资金执行层定位

  • 承接信贷核心放款指令，执行代付出款
  • 承接还款计划 / 催收指令，执行代扣、批量代扣
  • 交易结果实时回流信贷核心，驱动额度与账务状态
  • 对借款人提供快捷支付、协议支付等主动还款能力

双账户体系

  • 收款特约商户账户：还款代扣资金入账户，遵从收单管理办法结算约束
  • 放款支付账户：资金方（自有资金 / 消金主体）放款出金账户
  • 账户余额 / 日终核对，资金划拨与结算路径分户管理
  • 支持多资金方、多主体、多渠道账户并行

核心建设目标

  • 高可用：多通道冗余，异常自动降级熔断
  • 高成功率：智能路由 + 错峰重扣降低失败率
  • 低成本：费率 / 限额因子动态择优
  • 零资损：幂等 + 状态机 + 对账 + 差错池闭环
  • 快接入：新通道配置化上线，无需改码

总体分层架构

自上而下：业务接入 → 统一网关 → 支付业务中台 → 智能路由 → 通道适配 → 外部清算渠道；资金账务体系并行消费支付结果，横向支撑体系与基础设施托底。

资金安全与一致性保障

从幂等、状态、一致性机制、差错闭环、合规五个维度构建「零资损」防线。

全链路幂等设计

  • 支付流水号 + 业务单号双重去重
  • 网关层拦截重复指令，DB 唯一索引兜底
  • 回调 / 通知重复投递幂等消费
  • 重试请求复用原单，杜绝重复出款扣款

状态机驱动交易流转

  • 待支付 → 处理中 → 成功 / 失败 / 未知
  • 非法状态迁移拒绝，防状态跳跃错乱
  • 超时未明自动「主动查询 + 补偿」收敛终态
  • 终态变更串行化，保证事件顺序一致

跨系统最终一致性

  • 本地事务 + 可靠消息（事务消息 / 本地消息表）
  • 定时补偿任务扫描未闭环单据
  • 对账兜底：T+1 渠道对账 + 内部账账核对
  • 支付 ↔ 账务 ↔ 信贷核心三方金额一致

差错池与挂账机制

  • 退票 / 重复扣款 / 长短款 / 超时未明自动入池
  • 挂账登记 + 差错分类分级
  • 人工复核工作台，冲正 / 原路退款一键执行
  • 处理时效监控，杜绝差错沉淀为资损

通道容错与高可用

  • 多通道冗余互备，熔断降级自动切流
  • 维护窗口 / 异常通道自动屏蔽
  • 错峰重扣降低集中失败与通道限流冲击
  • 灰度切流控制新通道风险敞口

合规与审计

  • 银行卡号脱敏存储、展示、日志全链路
  • 证书密钥分级管理、定期轮换
  • 遵守《银行卡收单业务管理办法》结算约束
  • 操作留痕审计，满足监管检查要求
