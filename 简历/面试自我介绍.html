4第三阶段：AI 工程化三件事（重点，语速放慢）约 75 秒

近两三年我把重心转向 AI，做的不是几个零散工具，而是三件能进生产的事。

第一件，AI 自动化「开发·运行·测试」平台。参考 Harness Engineering 的思路：AI 编码的瓶颈不是模型不够强，而是环境规格不足——缺工具、缺上下文、缺反馈、缺「做完了」的判断标准。所以我用 AGENTS.md 加分层结构化文档做上下文治理，用新鲜度 linter 防止文档腐烂；自研 MCP 服务打通内网沙箱、线上日志和登录态，凭证由使用者本人保管、Agent 只读存在性；再用 linter 机械强制分层架构，报错信息里直接内嵌修复指令。最终打通「AI 编码 → 自动测试 → 自动部署 → 自动验证 → 日志排障」闭环，单接口迭代周期从半天级压缩到分钟级，现在已是团队标准研发工作流，研发者的角色从写代码上移为定需求、定验收、验结果。

第二件，房源发房自动审核 Agent。基于 LangGraph 状态机编排：图像、OCR、规则引擎、政府核验并行扇出后加权汇聚，条件边按置信度分档路由，检查点持久化让政府核验的异步回调可以断点复跑，图像和语音封装成子图做上下文隔离。工程上有三个我比较在意的点：房源描述是用户可控输入，要防提示词注入，所以把输入严格限制在数据区、做分隔符隔离，模型只输出 JSON Schema 约束的结构化判定，不允许自由文本影响路由；误杀成本远高于漏放，所以用非对称阈值，中间地带一律转人工；策略权重和阈值全部配置化，运营不用发版就能调。上线后自动审核覆盖率 80% 以上，优质房源分钟级上架。

第三件，运营客服知识库。传统知识库最大的毛病是知识滞后——需求每周迭代，文档停在上线那天。我提出「代码仓库 md 即知识库」：需求文档、接口说明、枚举字典、FAQ 随代码一起提交、Review、版本化，CI 触发增量更新，文档过期等同代码缺陷、在 CI 阶段拦截。检索侧按 Markdown 标题层级做语义切片、保留标题路径，向量加 ES 双路混合召回再重排，答案标注来源文件与行号可一键跳回源文档，避免模型自信编造。上线后人工咨询量下降约 80%，几乎看不到转研发的工单。

这一段是每个项目都留了「钩子」：环境规格、防注入、非对称阈值、知识滞后——面试官大概率顺着其中一个追问，详见下方「追问准备」。
5业务结果：证明不是技术演示约 25 秒

我比较在意 AI 的业务产出，而不只是技术跑通。在试点城市上线房源首图智能优选，点击量提升 0.67%、点击转化率提升 2.87%、链接曝光占比提升 3.56%；在场景卡片里新增 AI 金牌经纪人智能展位，对比旧版本展位转化率提升 46%，全直销城市每天新增约 200 条商机线索。技术侧和业务侧的结果是能对上的：一边是效率，一边是收入。

追问准备

讲稿里埋的钩子，面试官大概率会顺着问
Q1 · 为什么用 LangGraph，而不是线性流水线或低代码平台？
真实业务有异步外部回调（政府核验分钟到小时级）和人工审批挂起，需要状态机 + 检查点持久化做断点复跑；置信度分档要走条件边而非固定顺序；多算子并行扇出避免串行累加耗时；图像、语音封装子图做上下文隔离，只回传结构化结论。
Q2 · Agent 怎么防提示词注入？
房源描述、图片 OCR 都是用户可控输入。做法：严格限制在数据区 + 分隔符隔离 + 指令剥离；模型只输出 JSON Schema 约束的结构化判定，不允许自由文本影响路由；命中注入特征直接转人工。
Q3 · 自动审核误杀了优质房源怎么办？
误杀成本高于漏放（房东流失不可逆）→ 非对称阈值：放行阈值高、拦截阈值低，中间地带一律转人工而非自动驳回；按城市 / 类目灰度，人工复审结果持续回调阈值；因子权重与阈值配置化，运营自助调整不用发版。另外不做端到端大模型拍板，规则出确定性因子、模型出概率性因子，汇聚后输出命中因子清单，保证可解释、可申诉。
Q4 · Harness Engineering 到底解决什么问题？
瓶颈是环境规格不足，不是模型能力：缺工具、缺上下文、缺反馈、缺「做完了」的标准。四层解法：AGENTS.md 地图式文档 + 新鲜度 linter 与后台巡检 Agent；MCP 打通内网沙箱 / 日志 / 登录态（凭证本人保管、全量审计、高频日志拆 CLI 省 Token）；自愈式 linter 把修复指令写进报错 + 单向分层约束 + 测试红了拒绝 push；长任务进度文件 + git 历史交接，避免上下文耗尽后过早宣布完工或未验证就标记完成。
Q5 · 「代码仓库 md 即知识库」为什么能治知识滞后？
文档随代码提交、Review、版本化，上新需求即知识库生效；CI 监听 docs/、CHANGELOG、接口定义、枚举、FAQ 触发增量更新；文档过期等同代码缺陷，由新鲜度 linter 在 CI 拦截。检索侧按 Markdown 标题层级语义切片并保留标题路径，向量 + ES 混合召回 + 重排，答案引用溯源到文件行号可一键跳回；知识库还是客服 Agent 的上下文层，配合工具调用直接查订单、房源、审核状态，从「告诉你怎么做」变成「帮你把事办了」。
Q6 · AI 项目怎么衡量价值，不只是 demo？
分两类：效率——单接口迭代半天→分钟级、修复类需求 100% 沉淀回归用例、自动审核 80%+、人工咨询量降约 80%；增长——点击转化率 +2.87%、展位转化率 +46%、全直销城市日增约 200 条商机、链接曝光占比 +3.56%。
Q7 · 资金一致性 / 零资损具体怎么做？
全链路幂等（支付流水号 + 业务单号双重去重）、状态机驱动流转；跨系统「本地事务 + 可靠消息 + 定时补偿」保最终一致；差错池与挂账处理退票、重复扣款、长短款、超时未明；渠道 / 资金 / 账务多级对账逐笔勾兑、差异自动告警挂账；退款原路返回 + 幂等状态机杜绝重复退款；按「罚息 → 费用 → 利息 → 本金」优先级自动冲账。
Q8 · 为什么从支付 / 交易转做 AI？
不算转行，是把复杂业务的工程要求带进 AI 落地：资金系统里练出来的幂等、可解释、可追溯、高风险转人工，恰好就是 Agent 进生产最缺的东西（置信度分层、人机协同、引用溯源、灰度回滚都是同一套思维）。同时我做了十几年真实业务，知道指标在哪、谁能买单，不会只交付一个能跑的 demo。

  • 数字慢读、少读。开场最多 3 个；被追问时再展开完整口径与试点范围，显得数据可信。
  • 结尾主动收口。用「您看想先从哪块展开？」交还话头，不要以「我说完了」或长串致谢拖尾。
